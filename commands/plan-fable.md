用 Agent 工具启动 `planner-fable` 子代理，规划这个任务：

$ARGUMENTS

这是**只规划、不实现**的入口。要一路做到实现和审查，用 `/route`。决策权、模型路由的规矩和 `/route` 的「一、总则」一致：**待确认问题必须交给用户，不许替他挑；不给 planner-fable 传 model 参数。**

## 怎么执行

**第一步：启动，把背景带够。**

- 先跑 `date +%s` 记下开始时间，后面核模型用
- **不传 model 参数**——frontmatter 已钉 fable，Agent 工具的 model 参数会覆盖它
- 告诉它**规划文件的绝对路径**（一般是 `<项目根>/.route-plan.md`）
- 它看不到本会话的任何上下文。除了任务本身，还要写进 prompt：项目的绝对路径、相关的既有实现、之前讨论过的约束、已经排除的方案、用户说过的原话。**背景带不够，它只能猜，规划就废了**

**第二步：规划全文原样贴出，再问待确认问题。**

- 它返回的**规划全文原样贴进对话，一字不减**，不压缩、不只列要点
- 跑一次 `node ~/.claude/plugins/model-router/route-check.js --from <开始时间戳>`，确认它实际跑在 fable 上；出 ❌ 就停下来告诉用户，问要不要重跑
- 第 3 节「待确认问题」**只要不是空的，就用 `AskUserQuestion` 逐条问**（用户在本轮亲口说「这批都按你的推荐」才可以不问，且只管这一批）：「暂按」做法是第一个选项并标 `(Recommended)`，备选是其它选项，描述写选错的后果；一次最多 4 题，多了分批。**不要替用户回答，不要因为你觉得答案显然、默认做法代价小就跳过**——这一节是整个流程的价值所在
- 第 5 节「已自行决定」在全文里，用户有异议也一并转发

**第三步：把答案转发回同一个 agent。**

用户回答后，用 `SendMessage` 发给**同一个 agent**：「用户对待确认问题的答复：Q1 选……。请按修订规则更新规划文件。」

> ⚠️ 不要新起一个 agent。新起的会丢掉全部上下文，还要再烧一遍 token。

**第四步：呈现修订结果。**

planner 只返回修订摘要（改了哪几处、受影响步骤的新文件清单、新增的待确认问题），不会再给全文。**原样贴给用户**；有新增问题就回到第二步再问。用户想看修订后的全文，再 Read 规划文件贴出来。

**收尾：规划落地或放弃后，删掉规划文件**——它只是临时中转，留在项目里会被下一次 `/route` 当成上一轮的残留。要转去实现，直接打 `/route`，它会发现这份规划并问你接着用还是丢弃。

## 为什么绕这一圈

`planner-fable` 的 frontmatter 钉了 `model: fable`，所以规划**真的跑在 fable 上**（具体版本由 `settings.json` 的 `ANTHROPIC_DEFAULT_FABLE_MODEL` 决定）——而斜杠命令 frontmatter 里的 `model` 字段在手打命令时不生效（实测过），只有 agent 路径才生效。

同时子代理有独立上下文，规划时读的文件不会污染主会话、不会破坏主会话的 prompt cache。比 `/model fable` 切过去再切回来省约 8 倍 token（切模型会让缓存归零，实测一来一回约 29 万 token）。
