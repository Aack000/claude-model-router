做一次前端布局验收。页面地址：$ARGUMENTS

**前提**：本机装了 ui-guard（MCP 的 `ui_scan` / `ui_verify`，或 CLI `<ui-guard 仓库>/bin/ui-guard.js`）。没装或本轮没改前端 → 一句话说明跳过，不要建议安装，也不要自己造检查。

1. **地址**：参数优先；没给就向用户要 dev server 地址，不猜。`--actions "click:<选择器>"` 用于打开抽屉 / 气泡等交互后状态。
2. **双盲检测**（两份独立结果，互不参考）：
   - 派 `ui-auditor` 子代理：真正执行 ui-guard 扫描，输出机器报告（规则、selector、视口、状态、实测数据），并读截图核对。
   - 另派一个只读复核（`code-reviewer` 或 general-purpose）：**不要给它机器报告**，只给页面地址和截图，让它独立找问题。
   - 主会话比对两份结果：一致就采信；不一致用 `ui_verify` 或截图复核，并在汇报里写明差异和采信理由。
3. **修复**：硬错误当审查发现派修复子代理——不新增停点，主会话不直接改。疑似项只列给用户，不派活。
4. **回归**：修完用 `ui_verify` 核对 `new / persisting / fixed`。最多 3 轮，仍有硬错误就停下，把完整报告和路径交给用户。
5. **汇报**：机器报告、独立复核、两者差异、最终采信结论。
